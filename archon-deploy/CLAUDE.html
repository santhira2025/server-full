Repository Structure

This is a monorepo with two packages: - archon-api/ — Hono-based Node.js API server (TypeScript, ESM) - archon-app/ — React SPA frontend (TypeScript, Vite) - k8s/ — Kubernetes manifests (namespace, configmap, secrets, deployments, ingress, cert-manager)

Commands

API (archon-api/)

npm run dev            # Start with hot-reload via tsx watch
npm run build          # TypeScript compile to dist/
npm run start          # Run compiled output (production)
npm run test           # Type-check only (tsc --noEmit)
npm run test:auth      # Run auth integration test
npm run test:webhooks  # Run webhook integration test
npm run test:dedup     # Run dedup test
npm run test:all       # Run all integration tests (webhooks + auth)
npm run tunnel         # Start Smee webhook tunnel (programmatic, avoids smee-client v5 URL bug)
npm run tunnel:cli     # Start Smee webhook tunnel (CLI)

App (archon-app/)

npm run dev          # Start Vite dev server
npm run build        # Type-check (tsc -b) + Vite build to dist/
npm run lint         # ESLint (flat config, ESLint 9)
npm run preview      # Preview production build

Database (archon-api/)

npx drizzle-kit generate   # Generate migration from schema changes
npx drizzle-kit migrate    # Apply pending migrations
npx drizzle-kit studio     # Open Drizzle Studio GUI

Drizzle config reads DATABASE_URL from .env via dotenv/config.

Docker

Both packages have multi-stage Dockerfiles: - archon-api/Dockerfile — builds with tsc, runs as non-root archon user, exposes port 3000 - archon-app/Dockerfile — builds with Vite (accepts VITE_API_URL build arg), serves via nginx on port 80 with SPA routing

Architecture

API Server

Entry point: archon-api/src/index.ts — Hono app that mounts all route groups: - /api/* — authenticated API routes (repos, reviews, coaching, team, webhooks, tasks, events, billing, analytics, reports) - /api/v1 — public/external API (routes/api-v1.ts) - /api/admin — admin routes (routes/admin.ts) - /api/health — health check - /webhook/github — GitHub App webhooks (routes/webhook.ts) - /webhook/results — AI result callbacks (routes/results.ts)

GitHub webhook flow: - POST /webhook/github → routes/webhook.ts dispatches to handlers for issue comments, PRs, PR reviews, check suites, releases, installations, issues - In-memory deduplication by x-github-delivery header with 5-minute TTL - Commands triggered via /archon <subcommand> or /ac <subcommand> in issue/PR comments, or by adding the archon label

Core review pipeline: 1. services/review-pipeline.ts — orchestrator with progressive deepening (triage → review → self-check → validation loop) - Loads .archon/rules.yml from target repo for path-scoped review instructions - Self-check pass filters false positives before posting comments - Validation loop verifies generated code fixes (up to 2 retries) 2. services/smart-context.ts — priority-ranked context assembly (150K char budget across changed files, imports, importers, tests, memory, repo map) 3. services/repo-map.ts — generates condensed repo structure map (file exports, imports, signatures) cached as .archon/repo-map.json; supports 13+ languages 4. services/review-engine.ts — AI review logic; calls services/ai-proxy.ts for model routing 5. services/ai-proxy.ts — model tier routing: free/pro/team → Groq llama-3.3-70b-versatile with tier-based token limits 6. services/static-scanner.ts — zero-cost pre-AI static analysis (secrets, SQL injection, XSS, weak crypto, command injection, insecure config) 7. services/code-quality.ts — cyclomatic/cognitive complexity scoring, test coverage gap detection, dead code detection 8. services/feedback-learning.ts — tracks GitHub reactions to review comments, stores learnings, injects relevant past learnings into future prompts

Other key services: - services/auth.ts — GitHub OAuth flow + JWT creation/verification (7-day tokens) - services/github.ts — GitHub App installation token generation - services/coaching.ts — developer profile updates and learning from reviews - services/automation.ts — auto-labels, PR description generation, risk scoring, dependency audit, CI failure analysis, release notes - services/project-memory.ts — updates .archon/memory.md in repos on PR merge - services/integration-webhooks.ts — fan-out events to user-configured outbound webhooks - services/dispatcher.ts — alternative path that injects a temporary GitHub Actions workflow into the target repo

Auth middleware: lib/authz.ts exports requireAuthUser() (Bearer JWT → DB user lookup) and hasMinimumRole() for role checks. Roles: viewer < member < admin < owner.

Real-time: routes/sse.ts streams events/reviews/tasks via Server-Sent Events, polling DB every 10 seconds. Auth uses query-param token (?token=...) since EventSource doesn't support headers.

Database: Drizzle ORM with PostgreSQL (pg pool). Schema in src/db/schema.ts, client in src/db/client.ts. Key tables: organizations, users, repos, reviewResults, eventLogs, tasks, developerProfiles, learningEvents, integrationWebhooks, reviewLearnings, analyticsEvents, webhookDeliveries.

Frontend

Entry point: archon-app/src/main.tsx → App.tsx

Auth flow: GitHub OAuth redirect sets JWT in localStorage as archon_token. Token is included as Authorization: Bearer header via Axios interceptor in src/lib/api.ts.

API client: src/lib/api.ts — all API calls go through a single Axios instance with base URL from VITE_API_URL env var (defaults to http://localhost:3000).

Real-time updates: hooks/useRealtime.ts opens an SSE connection to /api/sse/stream. Also exports usePolling for polling-based data refresh. App.tsx shows toast notifications on new events/reviews.

Routing: React Router v7 with routes: /, /guide, /repos, /reviews, /coaching, /team, /webhooks, /tasks, /events, /billing, /analytics, /reports.

Key Patterns

  • All imports use .js extension even for .ts source files (ESM with TypeScript "type": "module")
  • verbatimModuleSyntax is enabled — use import type for type-only imports
  • GitHub App commands triggered via issue/PR comments matching /archon <subcommand> or /ac <subcommand>
  • Adding the archon label to an issue/PR also triggers the agent (issues → resolve, PRs → review)
  • The archon-token passed to dispatched agents is a base64-encoded JSON { orgId } — not the user JWT
  • Target repos can configure Archon via .archon/ directory: memory.md (project memory), rules.yml (path-scoped review instructions), repo-map.json (auto-generated), reports/ (generated reports)
  • Plan tiers: Free (unlimited requests, 8K tokens), Pro ($19/mo, 500 req, 8K tokens), Team ($49/mo, 2000 req, 8K tokens)
  • Tests run via tsx directly (the tests/ directory is excluded from tsc compilation)
